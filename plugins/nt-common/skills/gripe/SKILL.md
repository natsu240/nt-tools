# Claude 自身への改善依頼を投げる

依頼内容: $ARGUMENTS

作業中の会話を中断させずに、Claude Code のプラグインを直させるための入口だ。**この skill の仕事は「依頼文を作って投げる」ところまでで終わる。** 実際の修正は Orca が別に立てるワークツリーの中の Claude が最後まで進めるので、投げたらすぐ元の作業に戻れ。

## この skill を使う場面・使わない場面

- **使う**: skill の手順が実態に合っていない、hook が余計なところで止める、出力スタイルの書き方が読みにくい、サブエージェントが期待した動きをしない、確認が多すぎる/少なすぎる — つまり Claude Code の設定そのものを直したいとき
- **使うな**: 今作業しているプロジェクトのコード・仕様の話。それはその場で直せ

## 手順

### 1. 修正先を確定しろ

次を実行して、修正させるリポジトリの場所を得ろ。

```bash
bash "${CLAUDE_SKILL_DIR}/scripts/gripe-worker.sh" --resolve-repo
```

- パスが1行返れば、それが修正先だ。次へ進め
- `NOT_CONFIGURED` が返ったら、プラグインのリポジトリをどこに clone してあるかユーザーに聞き、答えを次で保存しろ。保存すれば次回以降は聞かれない

```bash
bash "${CLAUDE_SKILL_DIR}/scripts/gripe-worker.sh" --save-repo "<ユーザーが答えたパス>"
```

### 2. 依頼文を組み立てろ

$ARGUMENTS があればそれを不満の核として使い、**無ければ直近の会話から何に苛立ったのかを自分で読み取れ**。ユーザーに「何が不満でしたか」と聞き返すな（聞かれる手間を無くすための skill だ）。

依頼文は次の形で書け。**埋められない項目は見出しごと省け。推測で埋めるな。**

```markdown
## 何が起きたか

<実際に起きたことを、時系列で2〜4行。どのコマンド・どの操作の後に何が出たか>

## 何が不満か

<ユーザーの言葉をそのまま引く。言い換えて丸めるな>

## 手がかり

- 関係している skill / hook / 出力スタイル: <特定できた名前。分からなければこの行を省く>
- 実際に画面に出た文言: <原文のまま。長ければ該当部分だけ>
- 作業していたリポジトリ: <リポジトリ名>

## 希望

<どう直してほしいかをユーザーが言っていればそれを書く。言っていなければこの見出しごと省き、直し方の判断は向こうに委ねる>
```

書くときの決まり:

- **ユーザーの発言は原文のまま引け。** 「〜がうざい」を「〜の改善を希望」に言い換えるな。強い言い方のまま伝わったほうが、向こうで優先度と直し方を判断しやすい
- **自分で犯人を決めつけるな。** どの skill / hook が原因か特定できていないなら「手がかり」に事実だけ並べ、原因の断定は向こうに任せろ
- **画面に出た文言は原文のまま貼れ。** 要約すると、向こうがその文言でファイルを検索できなくなる

### 3. 承認を取れ

**組み立てた依頼文の全文を、会話の本文にそのままテキストとして出せ。** そのうえで AskUserQuestion で「投げる / 直す / やめる」を選ばせろ。**選択肢は3つだけにしろ**（投げた後は向こうが最後まで進めるので、内容だけは目を通してもらう）。

- **AskUserQuestion の `preview` に依頼文を詰めるだけで済ませるな。** 本文に出ていないと、何を承認させられているのか分からないまま選ばされる
- 本文に出すのは全文だ。要約・冒頭数行だけ・「以下の内容で投げます」の1行、のいずれも本文に出したことにするな

- **投げる**: 次へ進む
- **直す**: どこを直すか聞いて書き直し、もう一度出す
- **やめる**: 何もせず終わる

### 4. 投げろ

依頼文を Write でファイルに書き出し、次のコマンドで起動しろ。

```bash
bash "${CLAUDE_SKILL_DIR}/scripts/gripe-worker.sh" --run "<依頼文を書き出したファイルのパス>"
```

このコマンドは**すぐ返る**。Orca が修正先リポジトリに新しいワークツリーを作り、その中で Claude（Opus 5 / effort medium）を立ち上げて依頼文を渡す。**Orca が起動していないと失敗する**（そのときはコマンドの標準エラー出力をそのまま報告しろ）。

### 5. 元の作業に戻れ

起動した旨を1〜2行で報告して終われ。**進み具合を見に行くな。**待ったり、画面を覗いたり、完了を確認したりするな。進捗は Orca のサイドバーにカードとして出るので、ユーザーが見たいときに自分で見る。

報告に含めるのはこれだけだ:

- 投げたこと
- ワークツリーの名前とパス（`--run` が出力する）

## 覚えておくこと

- **並行して何件でも走らせられる。** 依頼ごとに別のワークツリーが立つので、順番待ちは無い
- **向こうの Claude は判断に迷ったらそのカードで止まって聞いてくる。** 止まっていることに気づくのはユーザーがカードを見たときなので、投げた側から催促するな。止まった依頼はそのカードで会話を続ければ再開できる
- **向こうの Claude は、リポジトリの CLAUDE.md と README を読んだ上で作業する。** バージョンの上げ忘れ・テストの失敗はリポジトリ側の検査で止まるので、壊れたものがそのままリリースされることはない
- **Claude Code を閉じても向こうは止まらないが、Orca を閉じると止まる**（Orca 管理下のターミナルで動いているため）
