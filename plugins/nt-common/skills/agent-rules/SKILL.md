# サブエージェント運用

## cross-session-message は転記・要約するな

他セッション（`claude -p` サブプロセス等）から `SendMessage`（cross-session-message）で届く中間状態報告は、ユーザーも直接見られる。ユーザーへの返答が必要な場面（判断を求められた・最終結果を報告する等）だけ言及すればいい。

## 独立並列タスクは1メッセージにまとめて呼べ

複数の独立したタスク（例: ドメイン領域ごとの調査を7件同時に走らせる）を、結果を待ってから使うつもりなら、**1つのメッセージに全員分の `Agent` 呼び出しを並べろ**。同一メッセージ内の複数ツール呼び出しは並列実行される。1件ずつ逐次投げて完了を待つ必要はない。

- Agent Teams（`team_name` 指定）は使うな。継続的な往復（SendMessage・idle 通知待ち・TeamDelete 後始末）が要る協業専用の重い仕組みで、一発勝負の並列調査には不要
- **委譲プロンプトには必ず「スキルを呼び出すな。別のサブエージェントへ再委譲するな。取得は自分で完結させろ」を含めろ。** 再委譲されると委譲先が孫の完了待ちで固まり、丸ごと遅くなる（固まってしまった後の対処は下の `TaskStop` の節にある）
- 1件ずつ呼んで待つ実装は、独立並列タスクの意味を成していない。速度が逐次実行と同じになるだけでなく、途中で hook に deny されたときに「並列できない」と誤解して余計に逐次化する失敗につながる

## コード調査サブエージェント（`nt-common:explorer`）の運用

- 1つのエージェントには調査テーマを1つだけ渡せ。複数詰めるとコンテキスト超過で失敗する。
- 調査テーマが複数あるなら `nt-common:explorer` を並列で複数立てろ。
- 浅い調査で誤った前提のまま進むな。手戻りで結局トークンも時間も無駄。
- プロンプトは2〜3行以内、ファイルパスの列挙は最大3〜4個。それ以上はディレクトリ指定 +「配下の全ファイル」で任せろ。
- 失敗したらさらに分割しろ（1ファイル1 エージェントでも可）。
- `Explore` は使うな（全 MCP スキーマを起動時ロードして枯渇する）。nt-common 未導入の環境では `general-purpose` を使え。

## 機械的出力要約サブエージェント（`nt-common:skimmer`）の運用

- Haiku 駆動・読み込み専用。
- 対象: git diff（大量変更）／ git log（多コミット）／ gh pr view ／ 数十KB 以上のログ・JSONL ／ 長文ドキュメント／大きな API レスポンス。
- 用途は「中身を読んで要点を抜く」のみ。コードベース探索・定義検索（地図作り）は explorer。
- **対象外**: 事実確認・編集根拠・コードレビューの対象本文（これらは原文のまま必要なので親で Read しろ。要約に丸めるな）。`nt-common:research` の一次ソース規約に照らして、一次ソース確認には使うな。

## 起動済みサブエージェントへの追加依頼は SendMessage で継続

- **起動済みサブエージェントへの返事・追加依頼は SendMessage で継続しろ**。サブエージェントが聞き返してきたとき・完了済みエージェントに追加作業を頼むときは、新規 Agent 起動でやり直さず、結果末尾の agentId へ SendMessage を送って文脈を保ったまま継続しろ。
- SendMessage が環境に無い（ToolSearch で見つからない）ときだけ新規起動にフォールバックしろ。

### SendMessage が処理されないときは TaskStop で親子とも止めろ

委譲先がさらに別のサブエージェントを起動していると、委譲先は孫の完了を await していてツール実行の合間が来ず、送った `SendMessage` が受信箱に溜まったまま処理されない。`/agents` のトークン数で、親が据え置きのまま孫だけ増え続けていればこの状態だ。

- 待っても届かない。**`TaskStop` を親・孫の両方に打って強制停止しろ**（孫だけ止めても親は await から戻らない）。
- 止めたあと、やり直すなら委譲先へ渡すプロンプトから再委譲の余地を消してから起動し直せ。
