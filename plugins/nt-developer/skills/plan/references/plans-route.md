# plans/*.md に書く場合

書き込み先が plans 経路に固定されたら、SKILL.md の「書き込み先の判定」から続けてこのファイルの手順を使え。

## 配置・命名

- **`plans/` は必ず本体のチェックアウト直下に置け。ワークツリーの中に作るな。** `plans/` は Git 管理外なのでワークツリーには引き継がれず、`orca worktree rm` でワークツリーごと消える。ワークツリーの中で作業していても、読み書きするのは本体側の `plans/` だ。本体のパスは `dirname "$(git rev-parse --path-format=absolute --git-common-dir)"` で出せ（以下このディレクトリを「本体のリポジトリルート」と書く）。
- **置き場所は「状態 → 管理表」の2階層で分けろ**: `<本体のリポジトリルート>/plans/<状態>/<管理表>/`
  - **状態**: `進行中`（作業中）→ `レビュー中`（`/pr` で PR を作成した後）→ `完了`（PR がマージされた後）の3段階だ
    - `進行中` → `レビュー中`: `/pr` で PR を作成すると `pr` skill 自身が自動で移す（詳細は `review` skill の「PR 作成後」節を見ろ）
    - `レビュー中` → `完了`: PR がマージされたら移せ（移し方は同 skill の「完了後」節を見ろ）
    - `レビュー中` → `進行中`: レビューで差し戻された場合に戻せ（詳細は同 skill の「レビュー結果の反映とコミット」節を見ろ）
  - **管理表**: そのチケットIDを採番した場所（`github` 等）を小文字で入れろ。チケット管理していない作業は `other` に置け。採番元の違うIDが混ざっても、どこで採番されたものかがディレクトリで分かるようにするためだ
  - 一覧が要るときは `find plans -type f -name '*.md'` を使え。状態・管理表がパスに出る
  - 今の管理表以外（Jira 等）で採番されたチケットを扱うことになったら、その名前でディレクトリを増やせ
- ファイル名: `<日本語タイトル>-<チケットID>.md`
  - **日本語タイトルを先頭に置け。チケットIDは末尾だ。** IDを先頭に置くと `ls` の並びが記号の羅列になって中身を思い出せない
  - **管理表はファイル名に入れるな。** 置き場所のディレクトリで分かる
  - 例: `plans/進行中/github/検索結果の並び替え機能追加-123.md` / `plans/完了/github/ログイン画面のUIリニューアル-104.md`
- `other`（チケット管理していない作業・チケット化しないと決めた作業）に置くものは `<日本語タイトル>.md` だけにしろ（IDは付けるな）。従来どおり、ファイル冒頭に「チケット化はしない（ユーザー判断）」のように番号を付けない理由を1行明記しろ
- ファイル名は日本語で書け。英語のケバブケースにするな（プロジェクトの文章の言語に揃える）
- **コミット対象から必ず除外しろ**。各リポジトリの `.gitignore` に個別追加するのではなく、全リポジトリ横断で効く個人の Git 設定に集約しろ（`**/plans/` はディレクトリ丸ごとの除外なので、状態・管理表の配下も対象に入る）:
  - 確認: `grep -q '^\*\*/plans/$' ~/.config/git/ignore 2>/dev/null`
  - 既に入っていれば何もするな。入っていなければ **設定ファイルへの追記に当たるため、追記していいか確認してから** `**/plans/` を1行追加しろ

## 作業中の計画書を記録しろ（ステータスライン表示用）

`${CLAUDE_SKILL_DIR}/../../references/plan-record.md` を Read し、その手順に従え（`implement` / `review` skill と共有している）。

## テンプレート

`${CLAUDE_SKILL_DIR}/references/plan-template.md` の見出しの並びをそのまま使え（冒頭の要約→実装ステップ→確認テスト→計画書レビュー→決めたこと→参照→背景→現状→変更後・対応内容→検証・完了条件→採らなかった案→この判断を覆す条件→触るファイル→未解決事項→今回やらないこと）。「AsIs」「ToBe」のような英語略語は使うな。「現状」「変更後」とプレーンな日本語で書け。
