# 計画書レビューの手順

書き終えた計画そのものを読み直し、抜け・食い違い・取り残しを探すための手順だ。**`plan` skill の確認テストに合格した直後、実装の承認を求める前に必ず通れ。**

**確認テストとこの手順は別物だ。** 確認テストは Claude が独断で置いた前提をユーザーへ提示して正誤を取るものだ。この手順は、計画に書いた内容が計画の中だけで完結して整合しているか、実際のコード・実行結果と合っているかを Claude 自身が検算するものだ。

## 呼ばれ間違いの検出

**この skill は計画本文と「確認テスト: 合格」の記録が揃っていることが前提だ。** どちらかが無いなら `plan` の担当だ。`/nt-developer:plan` を案内して止まれ。

**別セッションで回すな。** 計画を書いた会話をそのまま持っている状態でやれ。計画を書いた文脈が無いと、なぜその案を選んだかを知らないまま的外れな指摘を積むことになる。

## 入口で計画を全文読み直せ

**書いたときの記憶で判定するな。書いた本人でも必ず読み直せ。**

- **Issue 経路**: `gh issue view <番号> --json body --jq .body`
- **plans 経路**: Read で計画書を開け

要約・部分読みで済ませるな。折りたたんだ節の中身も全部読め。

## レビュー観点

下の観点を全部当てろ。**該当しない観点も「該当なし」と判定した理由を1行残せ。** 都合の悪い観点を握りつぶしていないかを読み手が確認できるようにするためだ。

| # | 観点 | 見るもの |
|---|---|---|
| 1 | 計画に書いた事実が実際と合っているか | テストの件数・API やコマンドの有無・画面の有無・ファイルの実在。**計画に書いた数字とパスは、その場でコマンドを叩いて確かめろ** |
| 2 | 実装ステップの抜け | 「変更内容の詳細」「触るファイル」に書いてあるのにステップに無いもの、逆にステップにあるのに触るファイルへ載っていないもの |
| 3 | 取り残された注記 | 「要確認」「保留」「後で決める」のまま残っている行。**残っているなら、この場で確定させるか未解決事項へ移せ** |
| 4 | 「決めたこと」表に無い分岐 | 本文で方式・配置・命名を選んでいるのに表へ載っていないもの |
| 5 | 「検証・完了条件」がそのまま実行できるか | 実行するコマンド・満たすべき数字が埋まっているか。「テストが通ること」だけの行を残すな |
| 6 | 参照している側の整合 | 変更する対象を参照している箇所が計画へ挙がっているか。**名前で grep して0件だったことを根拠にするな。** 機能を言い換えた文で書かれている箇所は名前検索に一切かからない |
| 7 | 選んだ方式が長期的に運用しやすいか | `${CLAUDE_SKILL_DIR}/../../references/quality-axes.md` の判断軸。**動くこと・実装が早く終わることだけを理由に方式を選んでいないか** |

## 見つけた項目の直し方

- **その場で直せるものは直せ。** 直したうえで「直した項目」として計画へ残せ
- **観点4に当たる分岐を見つけたら、`AskUserQuestion` で1問ずつ確定させろ。** 確定させたら「決めたこと」表へ追記し、`plan` skill の「確認テスト」をやり直せ。**新しい判断を抱えたまま古い「確認テスト: 合格」を残すな**
- **直さないと決めたものは、理由を添えて「直さなかった項目」として残せ。** 黙って落とすな
- 見つけた項目が1件も無いなら「見つけて直した項目: なし」と書け。**観点を当てた記録ごと省くな**

## 記録の書き方

計画に次の形で残せ。置き場所は「確認テスト」の記録の直後だ（Issue 経路は `plan` skill の `references/issue-body-template.md`、plans 経路は `references/plan-template.md` の該当節に従え）。

```
## 計画書レビュー

見つけて直した項目:

- <何が抜けていたか>。<どう直したか>

直さなかった項目:

- <何を見つけたか>。直さない理由: <理由>

計画書レビュー: 合格（<YYYY-MM-DD>）
```

**`計画書レビュー: 合格` を書けるのは、上の観点を全部当て終わって、直すと決めた項目を全部直した後だけだ。** 同梱 hook が、この記録が無い計画での実装の編集を deny する。

## 終わり方

記録を書いたら `plan` skill の「実装に着手する前に承認を取れ」へ戻れ。**この skill から実装へ入るな。**
