# 長期の運用しやすさで判断しろ

計画で方式を選ぶとき・実装するとき・差分をレビューするときに共通で使う判断軸だ。**規約の本体とコード例は `code-style` と領域別の `code-style-*` skill が持つ。ここには軸だけを書く。**

- **動くかどうかで方式を決めるな。半年後に別の人が直すときの手間で比べろ。** 今の実装が最短で終わることは、採用する理由にならない
- **読みやすさは、方式を選ぶ理由として動作の正しさと同列に扱え。** 読みにくい書き方を選ぶと、直す側が中身を読み解く時間を毎回払う
- **1行に収まるコメントは書いてよい。2行目以降だけ、その行が本当にコードの外側にある事実かを1行ずつ問い直せ**（残すか消すか・何行書くかの判定は `code-style` が持つ）
