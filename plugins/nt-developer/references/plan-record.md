# 作業中の計画書を記録しろ（ステータスライン表示用）

plans 経路のときだけ使う手順だ。`plan` / `implement` / `review` の3つの skill が共有する。

計画書を作ったら、**その場で「今このリポジトリで作業中の計画書はこれ」を記録しろ**。既にある計画書を開いて作業を再開したとき（実装セッション・レビューセッションの入口）も、同じコマンドで記録を上書きしろ。

```bash
REPO_ROOT=$(git rev-parse --show-toplevel)
mkdir -p "$HOME/.claude/state"
jq -cn --arg repo "$REPO_ROOT" --arg plan "$REPO_ROOT/plans/<状態>/<管理表>/<ファイル名>.md" '{repo: $repo, plan: $plan}' \
  > "$HOME/.claude/state/plan-current$(printf '%s' "$REPO_ROOT" | tr '/' '_').json"
```

- ステータスラインはこの記録を読んで計画書の行を出す。**記録が無いと、ブランチ名にチケット ID を含まないリポジトリ（`dev-<名字>` のような個人名ブランチ運用）では計画書の行が一切出ない**。`plans/` は Git の管理外なので `git diff` にも現れず、他に手がかりが無い
- **記録はセッションごとではなくリポジトリごとだ。** セッションを開き直しても同じ計画書が復元できるよう、意図的にセッション ID を名前に入れていない。セッションを分ける運用では、この記録が次のセッションへ計画書の場所を渡す唯一の手がかりになる
- 状態が `進行中` → `レビュー中` → `完了` と動いても記録を書き換えなくてよい。ファイル名を変えない運用なので、ステータスライン側が同じ名前を `plans/` 配下から探し直して追従する（`完了` へ移ったら表示から外し、記録も消える）
- ステータスラインを設定していない環境では、この JSON が1つ置かれるだけで何も起きない。確認を取らずに書け
