# PR をマージした直後にやること

`review` / `pr-followup` の2つの skill が共有する手順だ。**`gh pr merge` が成功した直後に必ず実行しろ。**

やることは2つだ。「デプロイ後にしか確認できない作業が残っているか」を見て残っていれば `deploy-watch` skill へ渡すことと、ワークツリーのセッションを閉じることだ。**この手順の中でデプロイを監視するな。**

## ワークツリーのセッションは閉じろ

**ワークツリーを畳む前に、計画（Issue の description / 計画書）が実際の差分と突き合わせて更新済みであることを確認しろ。** ワークツリーを畳むとその中の作業内容は参照できなくなる。未更新なら先に更新してから畳め。

- **本体フォルダで `gh pr merge` した場合は `sync-branch-after-pr-merge.sh` が既に畳んでいるため何もするな。**
- **ワークツリー内で `gh pr merge` まで進んだ場合**、未コミットの変更が残っていないことを確認したうえで、自分で `orca worktree rm --worktree path:<絶対パスへの参照> --run-hooks --json` を実行してワークツリーを畳んでから、直後にこのセッションを終えろ。
- **未コミットの変更が残っている場合は畳まず**、その旨を報告してセッションを終えろ。
- **デプロイ後の確認が残っていても、このセッションで待つな。** 本体のチェックアウトで新しいセッションを開いて `deploy-watch` を起こせ。

## 判定

計画の「検証・完了条件」を読み、未完のチェックボックス（`- [ ]`）が何件あるか数えろ。

- **Issue 経路**: `gh issue view <番号> --json body --jq .body` で description を全文読め
- **plans 経路**: 計画書を Read で全文読め

## 0件なら何もするな

そのまま終われ。**「念のため」で `deploy-watch` を起動するな。** デプロイを持たないリポジトリでは常に0件になる。

## 1件以上あるなら deploy-watch を案内しろ

次に打つコマンドをそのままコピペできる形で1行出して終われ。

```
/nt-developer:deploy-watch <Issue番号 または 計画書のパス>
```

**このコマンドは本体のチェックアウトで打て。** ワークツリーは畳まれるので、その中で開き直しても居場所が消える。

**この skill から続けて `deploy-watch` の中身を実行するな。** マージまで進んだセッションは既に差分・レビュー・PR の文脈を抱えており、そこへデプロイ後の作業を足すと1セッションが長くなりすぎる。**残っている未完タスクの件数と内容を1行で添えて、セッションを渡せ。**

例外は1つだけだ: ユーザーが「そのまま続けて」と明示したとき。
