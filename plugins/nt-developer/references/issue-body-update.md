# Issue の description を書き換えるときの反映のしかた

`plan` / `implement` / `review` の3つの skill が共有する手順だ。

**この手順は、新規作成・全面上書きの初回書き込みだけでなく、実装中の追記・セッションを閉じる前の書き戻し・レビュー後の更新・完了後の最終更新など、Issue の description を書き換える全ての場面で使え。** 一括置換のワンライナーで `--body` を直接組み立てるな（シェルのクォート・改行の扱いで本文が壊れる。実際に一括置換のワンライナーで本文を壊し、この手順に切り替えて復旧した事故がある）。

- 本文は Write でスクラッチパッド配下の `.md` に書き出し、`gh issue edit <番号> --body-file <パス>` で反映しろ。長文を `--body` にインラインで渡すな（本文中のクォートで壊れる）。ヒアドキュメントも使うな
- 反映が済んだら書き出した一時ファイルを消せ（退避した元 description は作業が終わるまで残せ）
- **description は全文置き換えになる。更新のたびに `gh issue view --json body` で最新を取り直してから組み立てろ**（他の人の編集を踏み潰さないため）
